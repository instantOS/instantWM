# Display Mirroring — Design Record

In-repo engineering record for output mirroring ("clone"). User docs live in
the instantos.github.io repo. `CHANGELOG.md` is autogenerated; never edit it.

## Model

A *mirror* head presents its *source* output's region of the logical desktop
instead of owning a region itself. The monitor layer sees one monitor for
both heads (KWin/Mutter model), so bars, tags, focus and layout never see two
monitors at one place.

- A mirror owns no position and no scale; config `position`/`scale` on a
  mirror are shadowed (warned, cleared by sanitization).
- A mirror keeps its own `resolution`, `refresh_rate` and `transform`: they
  describe the physical head. Wayland fits the source's content to them
  (`mirror_fit`: `contain` letterboxes, `cover` crops). X11 cannot scale and
  derives the mirror's mode from the source.
- A mirror whose source is disconnected or disabled is an ordinary output
  until the source returns. Heads that stop mirroring re-enter the desktop
  right of the layout (unless positioned by config) and automatic placement
  packs them.

## Shared (`src/output_mirror.rs`)

- `MirrorMap::build` validates declarations into a depth-1 map: no chains,
  cycles, self references or wildcard use. `sanitize_mirror_configs` repairs a
  config map (clears invalid declarations and shadowed fields, retargets
  relative anchors that name a mirror). Backends only see sanitized configs.
- `MirrorMap::active_pairs` yields the pairs whose heads are both active: the
  pairs a backend can realize.
- `fold_cloned_outputs` merges outputs that physically present the same
  region: an output inside another output's rectangle becomes one of its
  `BackendOutputInfo::mirrors`. This covers X11 mirrors (a CRTC inside its
  source's framebuffer region) and clones made by other tools
  (`xrandr --same-as`). For identical rectangles a declared source keeps its
  identity over its mirror, then existing monitor names, then names sort.

`OutputOps::get_outputs` reports logical regions; `monitor::logical_outputs`
folds them, and both monitor discovery and `monitor list` use it.
Applying policy is `OutputPolicyOps` on the backend contexts, because it
updates backend runtime state.

## Wayland

- `runtime.mirror_of` is the desired map. `runtime.realized_mirrors` is set
  only from applied output snapshots (`set_mirror_roles`): a pair is realized
  when both heads are enabled and the mirror carries its source's scale.
  Hot-unplug breaks pairs immediately (`drop_unavailable_mirrors`).
- A realized mirror is removed from the `Space` and its `wl_output` global is
  withdrawn (its layer surfaces are closed, captures and power objects
  failed). Every space consumer (input, hit-testing, layer shell, damage,
  workspaces) is therefore correct without mirror special cases.
- `OutputTransaction::apply_mirrors` runs before validation of every
  transaction and pins a mirror's position and scale to its source's. The
  scale must match because the mirror is rendered from elements built at the
  source's scale and each damage tracker measures elements at its own
  output's scale.
- DRM rendering (`render/mirror.rs`): a mirror frame is the source's scene
  elements wrapped in Smithay's `Crop` → `Rescale` → `Relocate` elements
  (`MirrorProjection`). Frame callbacks and client feedback follow the source.
  A mirror redraws whenever its source is dirty
  (`propagate_mirror_render_flags`) and follows its source's DPMS state.
  Touchscreens mapped to a mirror are inverted through the projection.
- `queue_output_policy_projection` releases heads that left the previous
  projection's mirror set (scale 1.0 unless configured, placed right of the
  layout unless positioned) and compacts automatic outputs, which also closes
  the hole a new mirror leaves.
- winit has a single output and never mirrors.

## X11

- `X11RuntimeConfig::mirror_heads` records the heads the policy glued. Only
  those are released, so external clones are left alone.
- `randr::apply_output_policy`: pass 1 applies every output that is not about
  to mirror a presenting source; pass 2 glues mirrors via the pure
  `mirror_policy_for` ladder (exact mode clones the source rectangle, else a
  centered 1:1 crop with a smaller same-aspect mode, else the head is
  disabled) and releases heads that stopped mirroring; then automatic outputs
  are compacted (mirror heads excluded, mirrors re-glued if sources moved)
  and the framebuffer is fitted.

## Known limitations

- X11 mirrors cannot scale. RandR CRTC transforms (`--scale-from`) could add
  scaling and `cover`, but not black bars for `contain`.
- A mirror has no `wl_output`, so clients cannot capture or power-manage it
  individually; capturing the source shows the same content.
