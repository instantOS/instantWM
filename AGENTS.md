This is a Wayland Compositor and X11 Window manager. 

Backends should be abstracted
away, so that we can support both X11 and Wayland without much effort. 

Do not do release builds as they take too much time and do not yield
improvements when just testing

CHANGELOG.md is autogenerated, do not edit manually. 

Documentation for this lives in https://github.com/instantOS/instantos.github.io, not here. 

Prefer direct domain collaborators and narrow parameters for new helpers.
Use WmCtx for coordination that needs native effects; context methods should
perform backend dispatch, not own policy decisions or model calculations.
Explicit field traversal is appropriate at ownership and dispatch boundaries.
Use scoped local component borrows for repeated access. Do not add forwarding
methods solely to shorten data paths, or temporarily change stored configuration
to communicate execution options to another operation.
